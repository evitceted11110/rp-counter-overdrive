# 《反擊超載》0.3.1：構築進入樂句中央（歷史文件）

> 0.4.0 已取代本文件中所有「改寫、插入、替換正式目標」的規則。構築仍必須留在三軌中央，但只能標記既有音符的得分、窗口、保險與連段價值；正式依據為 `design/spec.md` 與 `design/fixed-chart-score-0.4.0.md`。

狀態：`design_ready`

日期：2026-07-29

## 問題診斷

0.3.0 的構築規則有實際效果，卻被放在左右 HUD、卡片說明與戰後數字。戰鬥時玩家的合理注意力全部留在三軌目標，因此「看懂提示後按鍵」已足以完成大多數決策；Rogue 的取捨沒有佔用玩家正在看的地方。

0.3.1 的原則不是把更多戰鬥數字塞進畫面，而是讓每一個構築都改寫玩家下一眼會讀到的 4 格 response 樂句。玩家不必在命中壓力下回頭讀卡，也不必記憶隱藏加成。

## 新的注意力契約

### 1. 所有選擇先以中央「前後樂句」回答

起始核心、被動草稿與路線覆蓋層，都必須先顯示一條可演奏的 4 格 response 預覽，卡片文字只能是第二層資訊。

```text
原句   [ 左 ] [ 空 ] [ 右 ] [ 空 ]
改寫後 [ 左 ] [ 共振右 ] [ 右 ] [ 回聲 ]
操作   ←       →       →       無需按鍵
報酬                         共振回擊
```

- 四格順序固定等同下一個 response half，由左至右讀取；不是抽象圖示。
- `空` 必須可見，才能讓「把空拍改成目標」成為真實取捨。
- 會改變玩家輸入的格子必須標示鍵帽（`←`、`→`、`Space`）；自動回聲永遠標示「無需按鍵」，不可偽裝成第四輸入。
- 選定後立刻以同一條中央軌道播放 4 拍無傷害示範：先跑原句 1 次，再以染色／連線跑改寫句 1 次。示範完才進下一戰，不要把玩家帶到另一個說明畫面。

### 2. 戰鬥只顯示構築造成的「樂句痕跡」

觸發效果必須覆蓋在實際目標或其相鄰格，不新增需要注視的側欄。

| 家族 | 中央樂句痕跡 | 玩家當下真正決策 |
|---|---|---|
| 交替／共振 | 兩個相反側目標以青色導線連接，成功後尾格出現半透明回聲 | 是否追交替以拿回聲／加寬窗口 |
| 同側／棘輪 | 二連的第二格帶紅色窄環與 `超載 +1` | 是否承擔更窄第二拍 |
| 蓄能／保險 | 原本的空格翻為琥珀 `Space` 目標；命中後電荷沿中央軌前送 | 是否多按一個公開中央拍換保險／爆發 |
| 三相／序列 | `左→右→中央` 三格用三角導線連起，末格顯示金色破綻 | 是否為了三軌次序放棄較容易的單拍 |
| 切分／延遲 | 反拍格帶紫色後緣窗與回聲殘影 | 是否刻意在完美窗後半拍命中 |
| 恢復／斷路器 | 下一小節先顯示灰色「安全重寫」覆蓋，明確列出降低的目標密度 | 是否用較低輸出換拍感與連段重建 |

- HUD 僅保留構築名稱與一個家族色點，不能承擔觸發解釋。
- 每個已持有構築在首次觸發時，可用 0.6 秒短標籤貼在被改寫格上，例如「空拍 → 蓄能」。之後只保留視覺語法，避免遮擋節拍。
- 不要求玩家在戰鬥中點擊、瞄準、管理卡片或選擇戰鬥技能。

### 3. 路線必須是「下一戰會長什麼樣」而非獎勵標籤

路線覆蓋層固定同時展示兩條可比較的 4 格範例樂句，各自將改動格以家族色標出；選項名稱、獎勵家族置於其下。

| 路線 | 範例 response | 承諾的壓力 | 構築偏好 |
|---|---|---|---|
| 連打迴路 | `左 → 左 → 右 → 空` | 同側二連、八分交替較常出現 | 交替、同側、恢復 |
| 蓄能迴路 | `左 → Space → 空(可改寫) → Space` | 中央重拍與標記空拍較常出現 | 蓄能、三相、切分 |

路線只保證語法機率與獎勵家族，不承諾精確 phrase 順序；畫面必須用「範例，非固定順序」明示此界線。

## 每張卡的實演資料契約

`content/items.json` 的每個 core／passive 使用新增的 `phrase_preview` 欄位。它為 UI 提供資料，不取代 runtime effect：

- `baseline`：選擇前 4 格 response 範例，值為 `left`、`right`、`center`、`rest`。
- `rewritten`：效果成立後的 4 格範例。`echo`、`charge`、`insurance`、`vulnerability`、`late-echo`、`safe` 是呈現修飾，而不是新按鍵。
- `operation`：固定只可使用 `←`、`→`、`Space`、`無需按鍵`。
- `central_cue`：覆蓋在軌道上的短中文標籤；不得超過 8 個全形字。
- `payoff`、`cost`：玩家能在選卡前理解的結果與代價。

render 實作必須將修飾套在同一條 preview rail／實際 target 上，不把這些欄位渲染成另一張文字表格。

## 驗收補強

0.3.1 在既有 Gate 2／Gate 3 外新增：

- 草稿、核心與路線的每個選項都可在不閱讀段落文字時，從前後 4 格預覽說出「哪一格／哪一種序列會改變」。
- 選擇後 5 秒內，中央軌實演一次相同的改寫語法；沒有敵方傷害與額外按鍵要求。
- 在戰鬥錄影關閉 HUD 的情況下，評測者仍能辨認至少一種已持有構築正在生效。
- 至少 70% Gate 3 受測者在第一張草稿後能回答：「我選的東西讓下一句哪一格不同、我為何願意多承擔它。」
- 若移除所有 `phrase_preview` 與中央樂句痕跡後，受測者對構築差異的描述率沒有顯著下降，則此版失敗。

## 範圍控制

- 不新增按鍵、即時主動技能、瞄準、卡片連鎖或第四軌。
- 不把每次命中變成閱讀任務；中央標記僅在被改寫格及其下一格出現。
- 不改變既有傷害、窗口與生成規則，除非後續工程驗證發現 preview 與 runtime effect 不一致。
